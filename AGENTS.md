
- Portal value entry (employer/accounting_office) requires a valid, unused worker-list validation (validate-worker-list → contribution_worker_list_validations) enforced in set-contribution-value; why: backend must not trust the frontend gate.

- Signature links must be issued for a patient in the caller’s authorized clinic; official WhatsApp sends use the approved UTILITY URL template with a 24-hour single-use token and server-side consent, opt-out and audit gates.
- Affiliation welcome sends run only through send-affiliation-welcome after approval, with Meta-approved UTILITY template, clinic authorization, consent and a unique audit attempt per affiliation; why: prevent unauthorized or duplicate proactive sends.
- WhatsApp sends web actions as a single CTA button with a hashed, single-use, short-lived token (e.g. employer_portal_link_tokens redeemed by employer-portal-link); why: no data lists in chat and no reusable links, keeping Meta-compliant replies.
- WhatsApp "Gerar boleto" links (purpose generate_boleto_due) are bound to one competence a vencer and open /gerar-boleto; overdue competences only via Portal da Empresa; why: keep chat flow simple and Meta-safe.
- /sindicato app password recovery runs only through app-password-reset (CPF → official WhatsApp UTILITY URL template, hashed single-use 30-min link, rate limits, opt-out, audit); email code flow is only the fallback when no WhatsApp is available; SMS removed. Why: Meta-safe and simpler for members.
- Large pages keep extracted pure helpers, types and presentational dialogs in a sibling folder (e.g. src/pages/dashboard/calendar/, src/pages/employer-portal/); save/billing logic stays in the page. Why: reduce file size without risking data flows.
- Affiliation approval runs process-affiliation via the affiliation-documents function (idempotent: one auto ficha per associado, one valid 30-day card); portal boleto value entry is refused server-side in set-contribution-value while that employer has a pending affiliation acknowledgement; why: backend must enforce the ciência gate per CNPJ.
- Union entities without a clinic get an auto-created internal base account (clinics row with clinic_module_enabled=false, via trigger on union_entities); clinic menus/routes are hidden for it. Why: all union data is scoped by clinic_id, while the Clinic module must stay optional.
- Internal areas (/dashboard, /union, /admin) render inside the shared AppShell (collapsible AppSidebar + compact topbar); menu items come from the existing permission-filtered nav sources. Why: one consistent navigation without duplicating access rules.
- Internal page titles use the shared `PageHeader` (no card wrapper; one primary action, secondary actions in "Mais ações"), and the AppShell sidebar uses the dedicated `shell-*` color tokens; why: consistent compact layout without touching shadcn `sidebar-*` tokens used elsewhere.
- Shared UI building blocks (StatCard, FilterToolbar, StatusBadge, AlertBar, EmptyState, LoadingState, PageHeader) are exported from src/components/design-system; why: one premium visual standard across union, clinic and admin without duplicating components.
